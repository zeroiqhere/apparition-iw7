Apparition IW7 GSC source candidate

Current status

The source candidate now contains a menu, input controller, client HUD pool,
private-session guards, feature callbacks, and an opt-in GSC test suite.
All 376 GSC files compile for IW7 PC using GSC Tool 1.6.1.363.
No GSC runtime checks or gameplay acceptance tests have executed.
This is not a completed 1:1 Apparition port or an in-game-verified release.
The game installation has not been changed, launched, injected, or attached.

Selected-player and All Players Send Message

The original Options slot 11 and All Players slot 6 now open the keyboard with
one captured page and recipient. Selected messages retain the selected target,
while other keyboard routes retain the HUD owner as their menu target. All
manager routes require current Co-Host or Host access. The selected-host boundary
is retained for Options. All Players instead excludes only the sender, matching
MessageAllPlayers; the current host remains a recipient even for a Co-Host sender.
No fixed developer exemptions or persistent identities are introduced.

Confirmation validates entered text once, admits the current manager, takes a
detached recipient list, then rechecks current authority and recipient membership
before each per-player iprintlnbold. Sender-name cleanup and the exact green-name,
white-message prefix follow the two source functions. No waits, callback queues,
extra workers, Message Menu display setting changes or native player-state writes
are added. A submitted call has no native display receipt. Zero other recipients
disables the All Players row. No GSC assertion, native display or co-op execution
has been performed; source and bytecode checks establish the requested call path.

The tests-first gate rejected the absent keyboard action before implementation.
New GSC contracts cover formatting, invalid text/routes/owners, selected and lobby
rows, sole-host recipients, manager access and captured-target replacement. Normal
and developer compilation retain the suites without executing their assertions.

Source Keyboard for Messages and Doheart

Four source call sites now share one owner-scoped GSC keyboard modal.
The original thirteen strings, six rows, forty-five-character cap, input priority,
five-hundred-millisecond entry settle and per-action repeat delays are retained.
Action slots scroll, Use selects, Frag adds one space, Jump confirms, and Melee
deletes the last character or cancels empty input. Confirming empty input cancels.
The user chose the original Frag binding. Native game input handling, including
grenades, remains active; no weapon/input flags, counters or bindings are changed.

IW7 usinggamepad supplies input mode for the original horizontal-direction rule.
It is an analogue for BO3 GamepadUsedLast, with exact last-device semantics still
unverified. The grid uses native objective text, source spacing and a 130-pixel
panel. The existing main-pool scroller now supplies selection, including Basic's
usable pool handle. Native font spacing, cursor animation, key delivery and pixels
require game tests.

The controller feeds its one sampled button map to the modal and suspends ordinary
navigation. The captured menu session, page, recipient, HUD, current access and
exact verification grant must remain current. Closing, owner death or access loss
retires the keyboard through the existing HUD owner. There is no input worker or
new callback queue. Fourteen temporary text handles, or eleven numeric handles,
have one owned map; its keys are snapshotted before clearing handles, then native
destruction consumes each handle once. The main HUD alone owns the borrowed
scroller. A pending captured record is published before the source entry waits,
and the full input delay starts after visible setup and cursor placement.
Native allocation-failure behavior itself remains untested.

Custom Message validates the source alphabet/nonempty length and re-probes current
private-session membership, verification and configured Print Bold at confirmation.
Notify stays unavailable. Doheart uses a distinct typed-text route, permitting
validated custom text without treating it as a preset selector. Off-state edits
save text only; active edits preserve supported-style, same-value no-op and
allocate-before-stop rules. Cancellation invokes no consumer. No account,
inventory, perk, quest or native input state is changed by keyboard editing.
Profile and Anti-Join keyboard consumers and other numeric consumers remain
unported; Health Custom uses the shared NumberPad entry.

Contracts preceded each new model/session/input/consumer implementation. Source
and disassembly guards caught live-map cleanup iteration and early entry timing
before their fixes. Both normal and developer compilation retain all GSC checks;
the assertions, actual keyboard, message delivery and co-op have not executed.

Lobby Timer Options

wait placement. No derived deadline is stored on its record. At expiry it removes

Low Gravity and Super Speed

The full reference main.gsc:216-219 initializes BgGravity and GSpeed in
DefineMenuArrays, called from the current-host setup branch at line 347. This
corrects an early audit that missed those initializers. Functions/server.gsc:
225-230 compares the live setting with that one captured startup value. Equality
selects gravity 200 or speed 500; every other live value selects the startup
baseline. This includes an external third value. A preliminary inverse-on-enable
implementation was replaced before packaging because its branch differed from
the requested source behavior.

The candidate initializes one ID-keyed baseline array after supported private
normal Spaceland admission and before current/future player attachment. It
builds a local snapshot from readable typed native dvars, then publishes once.
Any defined snapshot, including an empty, partial or malformed one, blocks
later recapture. Probe and toggle never rewrite it. Missing or invalid startup
data leaves the setting unavailable instead of inventing a default. If startup
already equals the preset, both source branches produce the same result; the
row disables that fixed point and explains that no alternate value was captured.
The live checkbox remains separate from baseline readiness.

Official IW7-Mod gameplay.cpp at commit
37abcb260408ce7cdef0dde831bbfcad594510e3, Git blob
03b0992b9791c3381f487a1a26eaf4c6bd74bdf6, registers replicated bg_gravity as a

copied into the internal startup snapshot. There is no user-supplied speed value,
integer narrowing cast or claim that an arbitrary float is validated as int32.

The movement catalog contains only two fixed IDs, dvar names, native kinds and
targets. UI labels remain in the one source-ordered row list. Runtime snapshots
are keyed by those IDs; a struct/array integration mismatch was corrected with
tests first. Rows display the current value and exact next value but carry only
the ID to their callback. Selection re-probes current Co-Host/Host authority and native
data. There is no worker, second configured bit, cached current value, captured
command payload, automatic reset or per-player substitute.

Normal baseline, active target, external third-value, fractional gravity,
unknown/fixed-point baseline, invalid actor and malformed row contracts compile.
The opt-in initialization regression temporarily replaces only the menu's own
baseline field and restores it synchronously; its defined-snapshot path performs
no native dvar read or write. None of these GSC assertions has run. Actual speed,
gravity, getter/float behavior, engine consumers, loader-version compatibility,
co-op replication and gameplay acceptance remain unverified.

Teleport Gun event and lifetime binding

Original TeleportGun waits on player weapon_fired without a payload, then traces
that player's view and sets that player's origin. Native IW7 cp_weapon source
blob 196bdd5d3222a05e639377b910a9431e50396dca shows a player-started
sniperdustwatcher using the same payload-free event; other native watchers accept
an optional parameter. The gun ignores payloads and relies on current player
state. It adds no weapon grant, ammunition change, fabricated fire notification
or per-shot thread. Normal menu Crosshairs still traces the menu owner.

The shared teleport request now accepts an optional target_aim selector. Menu
calls omit it; gun shots pass true. Both paths use the same fresh role-aware
authority, target movement admission, ray construction and single native origin
setter. Only the owner-aim path checks the remote owner's movement readiness. A
dead requester does not prevent an otherwise admitted target from firing its
own enabled gun. Native travel/life blocks reject that shot without clearing
the configured gun, so the same entity can resume after the block clears.
There is no menu-open exclusion in the original gun, so none is invented here.
An actual weapon_fired while the menu is open can still request a move.

One transient apparition_teleport_gun record contains the requesting owner.
Its presence is configured intent, replacing the original standalone TeleportGun
Boolean; no duplicate enabled/active/listener-ready bit is stored. Toggle first
rechecks full authority for both enable and disable. Enable publishes the record
before starting one target-owned supervisor. That supervisor owns one on_shot
childthread and checks full current-roster/private role-aware target authority
every 0.05 s.
Losing requester authority releases the same record even if no shot arrives.
Each shot checks record identity before re-entering the shared fresh request.
There is no application queue or delayed replay of blocked shots.

Release rejects a stale expected record, snapshots the current one and clears
the player field before notifying that record. The record is its own stop source,
so an old notification cannot target a newer record's supervisor. A malformed
scalar setting clears without a notify on an invalid emitter. No separate stop
ticket, event generation counter or persistent attachment observer is needed.
The supervisor ends on that record stop, player disconnect or level game_ended;
GSC Tool syntax section7.5 documents that IW childthreads end with their parent.
The pinned official syntax file was fetched again and compared byte-for-byte.
This source contract does not prove actual installed VM scheduling behavior.

Controller unsupported-session handling and disconnect/game-end cleanup also
release the target's record. Ordinary menu close and death do not cancel it,
matching the original player-lifetime setting. The UI keeps Teleport Gun at its
source index4 and personal target. Actual-actor admission precedes record reads.
The checkbox/footer separate saved intent, the next toggle action and current
native movement pause; no native listener-ready or completed-move claim is made.
All five readiness fields must form a valid captured teleport view before those
saved-setting reads. The full Main/Players/Options/Teleport route remains intact.

Menu access, player identity and queued-action adaptation

The user's selected policy requires host verification before a guest can open
a menu. Original Menu/verification.gsc defines Bot, None, Verified, VIP, Admin,
Co-Host, Host, Developer; hasMenu accepts ranks above None. Player and lobby
Verification pages expose only None through Co-Host. The port preserves those
catalogs and thresholds. Native bot identity uses global isbot, token0x100,
backed by Aurora CODIW-Source d1a226dbd553229503290cfb73f8051ee3b34749,
scripts/hashed/3341.gsc blob fac3e4a8dc93925730d140b24ecb27047b78c04b.
The raw native player-command worker calls isbot on its player at line21.

Actual-player admission precedes bot/host calls. A grant requires the supported
private map, a fully admitted current roster, both current participants, a
native host owner and an assignable string. Self, bots, native hosts and a
same-level request are rejected. Only a changed grant writes apparition_access
and then prints one recipient message. Bulk requests reuse that same setter.
There are no fixed developer identities, developer privilege imports, native
identity writes or persistent verification records. Stored Host/Developer/Bot
strings do not grant those roles to nonhosts. Save Verification is unavailable.
The native host derives Host afresh; host migration behavior is untested.

The controller watches every resolved role transition and closes its HUD/editor
and recreates both menu sessions before accepting new input. None cannot open
either main or Quick Menu. Rows carry the access level at render; delayed
execution requires both fresh menu admission an identical current level
and the exact canonical grant reference before the callback pointer is called.
A changed grant replaces one {access:string} record rather than storing a separate
revision counter; restoring the same level cannot revive old queued rows. The
controller also observes grant-reference changes between monitor passes.
This closes the downgrade path where a
previously privileged submenu or queued row could survive Co-Host -> Verified.
The Teleport Gun checks its requester's access and the exact captured grant
reference both while idle and per shot.
The general gameplay authority helper remains separate: a native host can still
apply an effect to a guest who does not have permission to operate the menu.
Existing host-applied effects are not automatically reversed by menu revocation.

Original Main groups are reproduced in source order: Verified adds four base
entries, VIP adds seven, Admin adds four, and Co-Host adds four plus Players and
All Players. Host Menu and the unavailable Game Modes page are native-host-only
entries. The original GameModeSelected condition belongs to Apparition, but this
port has no mode-selection implementation or writer. Its unused view field and
third labels parameter were removed; no native state is read to hide this page.
The default unselected source position remains visible to the current native
host. Co-Host menu scope now follows the source-backed player controls: a
Co-Host may open Players and All Players, select current non-Host players, and
open their Basic Scripts, Teleport and Fun pages. A selected native Host remains
protected. The source lobby God Mode action includes the native Host. Down,
Teleport and Revive target current players other than the actual native Host;
an authorized Co-Host requester remains in that set. Crosshairs moves an included
requester last. Appended lobby Ammo, Equipment, Perks and Retain Perks,
Verification, and unrelated world/EE controls remain native-Host-only. These
role checks do not redefine the native-host identity used by other actions.
Guests start at None until the current Host grants a session role. Developer
identity and privileges remain unimplemented; no developer IDs are used.

Target-owned God/Ammo flags, Perk ownership and Retain Perks settings retain
their feature-defined lifetimes; this access change adds no revoke rollback.
Workers bound to an original grant recheck that grant and current personal
authority before continuing. Host-applied effects on an unverified guest remain
separate from menu access. GSC assertions and game behavior remain unrun. The package has
no native injector, full 1:1 parity is not established, and Freeze remains
unavailable while a reversible IW7 binding is unresolved.

Player rows and the selected Options title use [access] plus a cleaned name,
matching the source header structure. One canonical player_name::clean owns the
original token catalog for crosshair names and player labels; adjacent tokens
are consumed without skipping ordinary text. Empty cleaned names use a visible
Unnamed Player fallback. Identity remains the native player reference, never
the display name or a Steam ID. Stable keys take precedence over old row labels
and still require the captured actor, so simultaneous rename/reorder does not
move the highlight to another player. Native destinations retain their separate
point keys. A removed key uses a bounded visible cursor on the next rebuild.

Test-first records cover role resolution, source order, typed snapshots,
protected/no-op grants, host/roster denial, per-target and bulk descriptors,
status/name headers, missing names, duplicate/renamed player selection and
queued access changes. Normal/developer compilation and bytecode/source guards
are the observed checks. Assertions, native identity and messages, revocation
latency, grants/reconnect/migration, co-op behavior and exact HUD parity have not
been exercised in an IW7 VM. The official Apparition main commit and GSC Tool
latest release were fetched with curl again; they remain the pinned source and
release 1.6.1. No game process was launched, attached or mutated.

Zombie Options and native Death requests

The original Functions/zombies.gsc has thirty rows for a map outside The Giant
and Shadows of Evil: Knockdown is present, Push is omitted. The port now retains

Only Death is currently mapped. Selected-choice admission, footer reasons and

Death is a one-time current-roster request, independent of the UFO stage-five
wave worker. The probe builds its own detached list of eligible native agents, deduplicated
by actor reference so one pass cannot submit duplicate roster entries.
A fresh private-session/current-roster/living-host check precedes each packet;
the actor must still be an actual living agent, a tracked axis generic zombie
or clown, with known native killed callbacks, positive numeric health, a vector
origin, died_poorly equal0, no reservation and no defined dont_scriptkill field.
Brutes, unknown types and reserved quest actors remain outside this adapter.
The row carries no victim list; Use probes current state again.

The source health+666 margin is retained with bounded integer arithmetic.
Health must be numeric, positive, whole-valued and no greater than2147482981;
maxhealth must be numeric and at least current health. Health is converted below
the signed limit, then checked again as an integer before integer +666. The
second check handles float promotion near the first bound. maxhealth is not
converted. Review caught a draft2147483648 integer literal compiling as
-2147483648; bytecode regression guards now reject that wrapped guard. The test
contracts cover ordinary values, fractional input, the final safe signed packet
and a rounded near-limit float. These assertions remain unexecuted.

The native packet is enemy.doDamage(amount, origin, host, host, MOD_UNKNOWN).
The source two-argument Kill is adapted to a native player-attributed packet:
the audited clown killed handler performs radius damage on its nonplayer path.
Using a player attacker follows the same native branch already used by the
stage-five wave and dance assists. One request visits only its captured pass;
no recurring job, guessed event, health write, actor deletion, wave skip, quest
flag or death-counter write is introduced. A true return confirms submission,
not a kill receipt. IW7 can reject damage, cap it, or run normal scoring, loot,
wave progression and quest listeners for accepted hits.

Shared target policy now lives in zombie_targets. Wave and dance consume that
same implementation; the previous wave-owned copies and forwarding APIs are
absent. Existing target/protection/Brute/clown contracts were moved into its
mirrored suite rather than duplicated. New cases reject scalar actor/state
inputs, malformed callback tables, string health/origin and unknown bookkeeping
flags before field reads or native pointer/membership checks. The kill module
keeps only its packet-specific numeric normalization.

Zombie Movement request adapter

The source Movement slider at index9 retains Walk, Run, Sprint and Super Sprint,
with Walk as its initial preview. Walk/Run/Sprint now map to native walk/run/
sprint requests. Super Sprint has no verified mapping and remains visibly
unavailable. This is intermediate progress toward the requested full port; the
four-choice behavior and special-agent coverage are not complete.

A material source-name conflict was resolved before implementation. Friendly
Aurora files use a field named synctransients. The IW7 token table assigns
field token0x01F5 to movemode; the separate native function table assigns function
index0x1F5 to synctransients. Those namespaces are distinct. Pinned hashed3954
blob9ae4a641ef3a259a4bc324fd4800e238425ea4cd uses movemode, and the candidate
writes that field. No synctransients field or guessed speed multiplier is used.
This prevents a friendly-name mistake from compiling into an inert extra field.

The pinned native agent initializes slow_walk/walk/run/sprint tuning. Its
movement worker computes a baseline once, watches movemode changes, and sends
bb_requestmovetype when the mode differs from its cached value. A per-type
movemodefunc can replace it on later passes. The worker waits through scripted
locks, traversal and a defined frozen marker. Native Spaceland DJ code supplies
a corroborating direct sprint-request pattern, but its friendly field spelling
is not treated as canonical proof by itself. The native consumable slow-move
path can save and later restore another mode; no permanent ownership or lease
is inferred for this request.

blob59ccbcacd2e734c4f254dd84ca842bffa876aa85 initializes that field as a
struct. Hashed10 blob0451bc2ccc35a129fcdf0df569fc6c0a311df331 shows that the
native state-lock predicate reads statelocked (field token0x02C6). All evidence
uses Aurora CODIW-Source commit d1a226dbd553229503290cfb73f8051ee3b34749.

The probe scans level.agentarray, the same registry used by the native
getaliveagentsofteam helper. Actual entity/agent/life admission precedes pure
actor-field reads. The selector requires a known ordinary axis type, positive
numeric health, a known current mode, initialized ASM/blackboard structs and
valid native tuning. An undefined ASM current mode uses the established actor
mode fallback; a present unknown mode is rejected. Script locks, traversal,
any defined freeze marker, reservations, suicide bombers and crawler/dismember
states exclude the actor. Movement uses its own policy, without requiring the
death callbacks, countable-death flags, health margin or origin needed by Kill.

Each request rejects unmapped input before any native context read. It builds

player membership and each actual live agent's current membership/state before

contains no wait, event or spawned worker. No native rates, health, locks,
freeze state, wave counters or quest state are directly changed. Native tuning
is admitted by the initial probe; the inspected script calls do not yield
between that admission and the finite setter pass. No later-spawn policy or
permanent global mode is installed. A successful return means submission only.

Death and Movement now share one zombie_context authority/result provider.
Their obsolete local copies were removed. The UI also shares one snapshot
validation path, preserving host denial before missing/malformed/empty data.
The Movement row carries preview choices and display availability, without
captured target references, a checkbox or an active global mode value. Selection
uses fresh feature admission; a displayed snapshot cannot authorize a setter.

Contracts were written first for mode mapping, actor/state exclusions, malformed

movement request has executed. Acceptance, competing mode changes, clown ASM,
co-op and lifecycle behavior remain unverified.

Cursor and viewport presentation

The official Apparition main and latest GSC Tool release were rechecked with

The candidate owns the currently visible row groups plus a temporary outgoing group.
A pure transition plan uses the existing capacity/visible_start
rules, rejects changed counts, and compares retained labels/kinds plus optional
target, selection_key, destination and setting fields. Checked state and

row-identity cache or copied viewport formula was added.

capacity. Rotation happens before
color synchronization. Native MoveOverTime precedes retained target-y writes;
the incoming edge is placed immediately, initialized with its new scale, then
fades in. The outgoing edge stays at its old position and fades to zero.
Existing input cooldown exceeds the requested duration before another scroll.
After a positive fade duration, one bounded retirement worker checks the exact
spare reference and the HUD's released state, then destroys that outgoing group.
The caller passes the outgoing reference directly when starting the worker, so
later scheduling cannot capture a replacement spare at worker entry.
Zero-duration scrolling destroys it synchronously. Before another edge shift,
